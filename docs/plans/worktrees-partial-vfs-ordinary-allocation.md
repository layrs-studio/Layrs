## Ownership before effects

The ordinary adapter uses the genuine B export owner and protected image. Every
source observation occurs inside its retained private transaction and requires
the exact outgoing record, actual incoming admission, current closure and family
Ready membership. B's admitted lease never authorizes C.

C's holder owns independent `FamilyAccess`, lifecycle, parent, root, control,
member, metadata, database, FORMAT and lock pins. It does not borrow B's mutable
owner or retain a source SQL proof. This allows closing/reopening B while keeping
the actual C allocation alive. It does not allow reopening C from paths alone.

The ordinary parent uses `OrdinaryRootGuard`, exact directory identity and
ancestor exclusions for B and family/control/metadata. No Provider Session or
activation is fabricated. Catalog absence and B's actual retained protections
are checked under a catalog gate before/between effects.

Before creating files, a source SQL capacity probe reserves a conservative
maximum Copying encoding: actual canonical destination struct overhead, maximum
canonical three-u32 file identities, exact digest width and the enforced FORMAT
limit. Both per-record and complete-inventory limits must fit. The final actual
candidate is checked again before its exact source CAS.

## Durable boundaries

Allocation creates seven fresh artifacts: root, control, family member,
metadata, owner lock, private database and temporary FORMAT. Each attempted and
confirmed effect is retained in order. Partial failures retain acquired pins and
never delete, repair or adopt an uncertain artifact.

Planned-to-Copying binds the actual pinned destination proof under B's Immediate
writer transaction, rechecking source/image and C pins. The outgoing reader
recognizes Copying as live and validates the incoming family binding, canonical
member path, distinct private DB and genuine generation-zero snapshot/selection
commitments. Ordinary mutations stay fenced. Exact replay performs no SQL write.

FORMAT publication appends only a known prefix to the same allocated inode,
syncs, renames without overwrite, syncs the control directory and retains C's
owner lock. A retry verifies that same final inode and exact bytes. Copying
observations accept only an absent or exactly Initializing C registry entry.

Initializing registration authenticates two concrete source kinds through a
closed input enum. Existing Provider checks remain intact. The ordinary variant
borrows genuine same-snapshot admission and closure proofs and freshly checks B's
incoming admission against the family context. The common C kernel validates
exact member/database/FORMAT and no destination roots/reservations/installations.
Its independent family writer commits and positively closes while source and
destination holders remain live.

## Cancellation and recovery limits

Allocation can leave real resources while SQL is still Planned. Public
preallocation cancellation therefore retains actual parent/worktrees/family and
catalog gates, requires both destination namespaces and catalog ownership to be
absent, and holds those guards through source COMMIT. Any existing entry refuses,
including foreign entries. It does not infer that an entry is safe to remove.
Terminal Cancelled retries do not inspect or change a later namespace.

After partial allocation, B remains mutation-fenced until a future explicit
resource-aware recovery protocol resolves the live operation. A new nonce alone
cannot bypass it. Dropping an allocation holder or crashing does not grant a
path-based resume capability. Resource-bearing cancellation, orphan resolution
and crash recovery still require implementation and their own qualification.

snapshot/selection. `copy_verified_prefix` already accepts genuine admitted

needs to recognize populated v2 `projection_restore_history`, currently omitted
from its copied-row exceptions.

Reservation coexistence has three independent fences to preserve or specialize:
B's retained-family validator rejects an active unretained C group; the existing
import reservation reader rejects any exact installations; and the exact-content
reader currently rejects foreign reservation IDs while counting all exact rows.
A dedicated export policy must account for B's retained groups and exactly one
active C target, with C-scoped installation interpretation. Removing these checks
globally would widen ordinary and Provider authority and is not the intended fix.
