- Politique approuvée : une base réelle/deux côtés, identité exacte type + objet + mode, source disparue/destination nouvelle ; relation fiable uniquement si cette identité n'a qu'une occurrence dans la base et dans le côté. Aucune heuristique de similarité ni choix lexicographique entre duplications.
- Livré : `graph_merge::renames::analyze_renames(objects,base,[headA,headB],limits)` retourne `RenameAnalysis {policy,exact,ambiguous,conflicts}`. Modèle normatif `PlannedRenameConflict` : toutes les valeurs/absences aux placements, vrais Steps sources, IDs JCS triés, aucune variante tronquée. `from_canonical_bytes(bytes,objects,limits)` reconstruit depuis les vrais Trees ; `select_term(termId)` retourne les valeurs de **tous** les placements à appliquer ensemble, pas un Step accepté.
- Ancêtres dont présence/type change conservés en placements `affected`, sans assimiler un hash de répertoire modifié à un renommage fiable. Cela préserve les répertoires créés/supprimés et évite de laisser un répertoire vide inventé après sélection ; répertoires toujours présents comme Trees non englobés inutilement. Aucun détecteur de renommage de répertoire vide.
- Garde transitoire remplacée par l'admission locale : `PlannedConflict` accepte la forme exacte, `anchor_paths` désigne toutes les occurrences requises, `validate_rename_context` reproduit l'analyse depuis les vrais Trees. APIs natives existantes `preview_conflict_resolution`/`accept_conflict_resolution`, choix d'un terme entier seulement. Les mouvements unilatéraux ou vers la même destination restent exacts ; ambiguïtés non concurrentes restent une analyse explicite et un changement delete/add sans appariement choisi. Re-fusion d'un Conflict multi-placement toujours refusée explicitement.
- Preuves : **9 nouveaux tests**, rename/modify, rename/delete, rename/rename, collision de destination et deux sources, répétitions, copie/contenu modifié/mode non reconnus arbitrairement, symlink, ancêtres, permutation, contexte corrompu/manquant et quotas. Windows weave lib **52 PASS / 1 fixture sous-processus ignorée**, régression `native_rewrite` **7 PASS 23,43 s**, Clippy all-targets strict PASS. Linux Docker Rust1.90 sans réseau/source lecture seule : graphe **31 PASS 0,10 s**, dont ces neuf ; IDs golden exacts `A.txt`, `é.txt`, `É.txt` identiques sur les deux OS.
- Reste : macOS/autres architectures, qualification de toutes les combinaisons hors matrice publiée, migration du manifeste Lens code historique (profil natif 1.1 opt-in déjà exécuté).
